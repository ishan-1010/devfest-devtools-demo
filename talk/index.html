Bug 1: Console

The list says "Loading events..." and never changes. The Console prints:

Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')   app.js:45

Line 45 is search.addEventListener(...). search is null, so getElementById('search') found nothing. The script sits in the head and runs before the browser has read the body. Pause on the first line of app.js and open Elements: there is no body yet.

<script src="app.js"></script><script src="app.js" defer></script>
Because getElementById returned null, when app.js ran inside the head, on first load.

Bug 2: Network

With bug 1 fixed, the Console says Unexpected token '<', "<!DOCTYPE "... is not valid JSON. That sounds like broken data. Open the Network tab, find the row named events, and read its status: 404. Open the Response tab: it is an HTML page that says Cannot GET /api/events. The data was fine. The address was wrong.

const res = await fetch('/api/events');const res = await fetch('/api/events.json');

A 404 does not mean the server is down. It means the server is fine and nothing is at that address. Before you edit code, you can test the fix in DevTools: right-click the request and resend it as a fetch.

Because the response was a 404 HTML page, when the page fetched /api/events, on every load.

Once it works, look at the Size column. The data is 490 KB for 4000 events, sent uncompressed by my demo server. Real servers usually compress. Try the Slow 4G throttle and watch the Time column.

Bug 3: Performance

On a laptop, typing feels fine. Your user is on a phone. Throttle first (CPU 4x slowdown and Slow 4G), then record, type "flutter", and stop. Look for tasks with a red corner: they ran longer than 50 ms. Open Bottom-Up to see where the time went. In my runs it was Layout, render, editDistance and score.

Every keystroke scored all 4000 events letter by letter, sorted them, and rebuilt the list. Typing "f" matches 2001 events, so it drew 2001 cards. The browser has one main thread. While it runs your function, it cannot paint.

Debounce

Wait 150 ms after the last key.

Prepare once

Build the lowercase search text one time.

Plain includes

No scoring, no sorting.

Show 50

Render only the first 50 results.

let timer;search.addEventListener('input', () => {  clearTimeout(timer);  timer = setTimeout(() => {    const q = search.value.trim().toLowerCase();    const hits = filter(q);          // text built once    render(hits, hits.length);       // first 50 only  }, 150);});
Because one input handler ran for hundreds of milliseconds, when the user typed in search, on a throttled mobile CPU.

My own test runs, on a Mac with Chrome 159, CPU 4x slowdown and Slow 4G: the slow page had an INP of 378 to 671 ms across three runs, and the fixed page 16 ms. Your numbers will differ. Measure your own.

Why this matters in India

  • Android is 94.84% of mobile devices in India, October 2026. StatCounter.
  • 77% of mobile sites have good INP (200 ms or less), against 97% of desktop sites. HTTP Archive, Web Almanac 2025.
  • redBus cut its search page INP from 870 to 900 ms down to 350 to 370 ms, and reports a 7% overall increase in sales. The article gives no period or control group, so read it as their report. web.dev case study.
  • INP: good is 200 ms or less, poor is over 500 ms. web.dev.

A 4x CPU slowdown is 4x slower than your own laptop. It is not a budget phone. Test on a real phone when you can.

AI assistance in DevTools

Turn it on in DevTools Settings, under AI innovations. You must opt in and sign in, you must be 18 or older, and Chrome labels it experimental.

Read this first

The Settings page says that Console Insights sends the console message, its stack trace, related source code and network headers to Google, and that AI assistance sends chat messages, data the page exposes to DevTools, and what you select (requests, files, performance traces). It says human reviewers may see this. Do not use it on pages with private data.

My use: form your own read first, then ask. On this demo I asked "why is typing slow?" and it named score, editDistance, rebuilding the list with innerHTML on every input, and no debounce. It matched what I had found. It also suggested a Web Worker, which is more than this page needs. Check every number and every cause in the trace before you put it in a bug report.
